# supportCheck hosting and cost guardrail

Status: **PROPOSED / ACCOUNT-SPECIFIC COST EVIDENCE REQUIRED / INDEPENDENT REVIEW REQUIRED**

Issue #219 identifies two different cost risks that must not be conflated:

1. **fixed hosting cost** of the selected SageMaker real-time endpoint;
2. **usage pressure** from supportCheck invocations generated by Assistant claims.

## Hosting decision gate

The current privacy-qualified candidate remains a SageMaker **real-time endpoint**. This document does not select an instance type or claim a monthly price.

Before endpoint deployment, record and review:

- AWS account and region;
- exact instance type;
- initial/min/max instance count;
- autoscaling policy, if any;
- current account/region price source and timestamp;
- estimated hourly and 30-day steady-state cost at minimum capacity;
- expected staging schedule (always-on vs intentionally stopped outside exercises);
- measured memory/CPU/latency suitability for the frozen checker container.

No production authorization may infer a price from a different region, date, or instance family.

## Usage circuit-breaker

A checker request budget should use the existing content-free KV pattern, but count **supportCheck invocations**, not query text, topics, evidence text, or user identifiers.

Proposed controls:

- `RESEARCH_ASSISTANT_SUPPORT_CHECK_DAILY_INVOCATION_LIMIT`: explicit positive integer; absent/invalid means checker remains fail-closed once usage-budget enforcement is enabled.
- UTC daily KV counter: `assistant:supportcheck:invocations:YYYY-MM-DD`.
- Check budget before each semantic checker invocation.
- Record one unit only for an attempted checker invocation.
- At or above the limit: reject the claim with a machine-internal budget reason; response boundary remains all-or-nothing.
- KV budget read/write failure: fail closed for checker use.
- No automatic retry.
- Operational pause (#218) has precedence: paused means no checker invocation and therefore no usage increment.

The daily limit is **not frozen here**. It must be set prospectively from non-user-derived staging load/cost evidence plus the chosen endpoint capacity. Do not tune it from real-user query content.

## Fixed-cost guardrail

An invocation counter cannot stop the fixed hourly charge of a provisioned real-time endpoint. Therefore endpoint lifecycle is a separate operational control:

- staging endpoint may be intentionally stopped/deleted outside authorized exercises if reproducible provisioning is available;
- production minimum capacity and any autoscaling floor require explicit cost acceptance;
- a billing alarm/budget in the LibEdge AWS account should cover SageMaker spend independently of application KV counters.

## Evidence before production

The Product Readiness packet must include exact hosting configuration, current price evidence, measured checker latency/throughput, observed invocations per answer, proposed daily invocation limit and rationale, AWS billing alarm/budget evidence, and a tested circuit-breaker fail-closed result.

This proposal does not deploy an endpoint, set a monetary budget, enable supportCheck, or authorize production.
